<known_defects>
Read `packages/core/src/evaluator.ts` before starting. Two confirmed bugs:

**Bug 1 — groups never recurse (`evaluator.ts:33-37`).** The group branch destructures
`conditions` and passes the raw array of condition *objects* straight into
`groupOperators[operator]`, which expects `boolean[]`. Because every object is truthy:
- `AND` returns `true` for any non-empty group, regardless of the conditions
- `OR` returns `true` for any non-empty group
- `NAND` / `NOR` return `false` for any non-empty group
- `XOR` returns `true` only when the group happens to hold exactly one condition

So a rule with any nested group fires or fails based on how many conditions it has, not
what they say. Leaf conditions inside a group are never evaluated at all.

**Bug 2 — custom operators are unreachable (`evaluator.ts:60-72`).** `registerOperator`
writes into a `customOperators` Map, and `getOperator` reads it, but `evaluateCondition`
consults only the built-in `groupOperators` object. Nothing registered is ever called.

Note `CustomOperatorSchema` in `types.ts` types `evaluate` as `(boolean[]) => boolean`,
so custom operators are **group-level** operators (same shape as the built-ins), not leaf
comparison operators. Do not redesign this — match the existing contract.
</known_defects>
