<task type="auto">
  <name>Task 1: Install Vitest and register a test task in Turbo</name>
  <files>package.json, turbo.json</files>
  <action>
Add `vitest` (^3) to root `devDependencies` and a root script `"test": "turbo run test"`.
Install with `pnpm add -Dw vitest` so it lands in the workspace root rather than a package.

In `turbo.json`, add a `test` task to `tasks`:
```json
"test": { "outputs": [] }
```
Do NOT give it `"dependsOn": ["^build"]`. Workspace packages here export raw `.ts`
source (`@repo/core` → `./src/evaluators.ts`) and the apps compile them directly — the
`dist/` output that `build` emits is not what anything consumes. Adding a build
dependency would make every test run pay for a `tsc` pass that changes nothing.

Do not set `"cache": false` — test results are cacheable on unchanged inputs and that
is most of Turbo's value here.
  </action>
  <verify>`pnpm install` succeeds; `npx turbo run test --dry-run=json` lists the `test` task without error</verify>
  <done>Root `package.json` has a `test` script and `vitest` devDependency; `turbo.json` has a `test` task with no build dependency</done>
</task>

<task type="auto">
  <name>Task 2: Wire Vitest into @repo/core with a smoke test</name>
  <files>packages/core/package.json, packages/core/vitest.config.ts, packages/core/src/evaluator.test.ts</files>
  <action>
Add `vitest` to `packages/core` devDependencies and a `"test": "vitest run"` script
(use `vitest run`, not bare `vitest` — bare enters watch mode and would hang Turbo).

Create `packages/core/vitest.config.ts` with `test.include: ['src/**/*.test.ts']` and
`environment: 'node'`. Keep it minimal; no coverage config yet.

Create `packages/core/src/evaluator.test.ts` as a smoke test that imports from the
package's own source (`./evaluators`) and asserts one true statement about
`executeRules` — e.g. that an empty rules array returns an empty Map.

Import `{ describe, it, expect }` explicitly from `'vitest'`. Do NOT enable
`globals: true`: that requires adding `"types": ["vitest/globals"]` to
`packages/core/tsconfig.json`, and `pnpm check-types` runs `tsc` over the same files —
explicit imports keep the type-check green without touching tsconfig.

Note `packages/core/tsconfig.json` overrides the shared base with `target: es5` and
`moduleResolution: node`. Leave it alone in this plan — Vitest transforms via esbuild
and does not read `target` from tsconfig, so the tests run regardless. Changing it is
out of scope here and risks the existing `build` script.
  </action>
  <verify>`pnpm --filter @repo/core test` passes with 1 test; `pnpm check-types` still passes</verify>
  <done>A passing test file exists in `@repo/core`; the package has a non-watch `test` script; type-check is unbroken</done>
</task>
